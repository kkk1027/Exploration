# P14 候选落点倾向（先远后近）—— 前置准备与实施记录

**日期**：2026-11-11
**用户需求（原文）**：
> 候选序列内先去当前位姿下最远的未知格内候选，再去剩下未探索的未知格内候选，
> 达到先探索出室内大致框架、再逐步补齐室内未知区域的目的。

**硬约束（用户明确）**：**只做候选序列内的排序**，不改候选生成策略
（RRT / 前沿提取一律不动），只在可用候选内重选。

---

## 1. 为什么不是"重做 8cc16a4"

历史提交 `8cc16a4` 做过一次"区域新度优先"，78 分钟后被 `1edaae8` 回滚。回滚依据
（`nw5` vs `rs5`，同物理配置只改打分）：

| 指标 | rs5 | nw5 | 变化 |
|---|---|---|---|
| 停滞中位 | 9 s | **56 s** | ×6.2 |
| PASS | 5/5 | 2/5 | — |
| 已知面积 | 159.7 m² | 144.8 m² | −14.9 |
| 接触 | 0 轮 | 1 轮（3 段） | — |

**机制**：那次的权重 `novelty_w × (2 m 未知格数)` 把车推向**远区**，而实测远区目标
69% 走不到 → 取消 → 进黑名单 → 候选池更快耗尽 → 长时间停滞。

**关键区别**：用户这次要的是**距离排序**（越远越优先），而 `8cc16a4` 是
**新度排序**（未知格多优先），两者目标不同；但**失败机制相同**（都推向远区）。
所以 P5 的可达性把关不是可选优化，而是方案能否成立的前提。

## 2. 前置阶段实测发现（推翻了方案 (A) 的原始形态）

### 2.1 未知连通分量在本世界是退化的

用 `p13s4_g1` 的真实 `map.pgm`（234×386 @5cm）统计：

| 项 | 值 |
|---|---|
| 未知格总数 | 30266（33.5%） |
| 未知连通分量数 | 150 |
| **最大分量** | **27678 格 / 69.20 m²** |
| 其余 149 个分量合计 | 6.47 m² |
| 最大分量占比 | **91.4%** |

后果（用 `cand_pool.jsonl` 实测）：

| 特征 | 拍内归一化极差（中位） | 判定 |
|---|---|---|
| `dist` 候选自身距离 | 83.4% | ✅ 可排序 |
| `u_eff` 未知格数 | 213.9% | ✅ 可排序 |
| `reg_far` 所属区域最远点距离 | **0.0%** | ❌ **无区分度** |
| `reg_cen` 所属区域质心距离 | 0.0% | ❌ 无区分度 |
| `depth` 未知厚度 | **160.9%** | ✅ 可排序 |

**结论**：方案 (A) 若按"所属区域最远点距离"排序，84.9% 的候选都是同一个数，
排序结果与改造前完全相同 —— 等于没改。

### 2.2 替代特征：未知厚度 `depth`

`depth` = 该未知格到最近**已知格**的距离（`ndimage.distance_transform_edt`）。
房间中心厚、门框/走廊处薄，天然区分"房间"与"连接处"。

- 实测：最大 3.61 m、未知区均值 0.74 m、拍内归一化极差 160.9%
- 单测 `H`：大块 0.75 m vs 小块 0.00 m

### 2.3 阶段判据 (a) 用"最远前沿距离"是噪声

第一版用 `unknown_edge_far()`（紧邻已知空闲的未知格中离车最远的距离）。
实测 90 s 内：**上涨 40 拍 / 下跌 38 拍**，单拍最大变动 1.27 m，纯随机抖动。

直接后果：90 s 内阶段切换 **3 次**（框架→补齐→框架→补齐），两阶段互相抵消，
"先远"根本跑不出来。

**改为已探明格数`known_cells()`**（单调递增）后：第二轮冒烟只在真正发现新区域时
切换（58923 → 61455，+2532 格）。

### 2.4 远目标准入阈值不能用 `corridor_hard`

第一版用 `corridor_hard = 0.92`，实测单轮否决 **35 次**，全部卡在
"实测 0.90 m vs 门槛 0.92 m"这 2 cm 差异上 —— 属于测量噪声，不是真的窄。
改用 `pass_width = 0.90`（车宽 + 2×安全余量的通行下限）后降到 **4 次**。

### 3.2 新增方法

| 方法 | 作用 |
|---|---|

| `relay_point(gx, gy)` | 沿原目标已算出路径取中继点 |
| `probe_pool(scored, raw_of)` | 候选池快照落盘 |

### 3.3 排序规则

```
补齐阶段（frame_far_first=false 或已切换）：
    sorted(items, reverse=True)          # 与改造前逐位等价
框架阶段：
    sorted(items, key=(negd, -score))    # negd = -距离，升序 = 距离降序 = 越远越优先
```

**为什么不把距离塞进第一个元素**：下游 `top.append((u - pen - risk_pen, negd, x, y))`
里 `pen`/`risk` 是百~千量级罚分，会把米级的距离彻底淹没。改排序规则、不改元组
结构，是唯一不动下游三处解包的做法。

### 3.4 框架阶段的三个配套改动

1. **不做距离折现**：`risk_discount(d) = 1/(1+(d/4.5)²)` 是单调递减的，
   和"越远越优先"方向相反。框架阶段直接取 `p = 1.0`。
2. **强制关掉 `near_first_reorder`**：它会在 ±10% 分差带内把近的候选提前。
3. **`passing` 不再按 score 排序**：保持 `top` 的距离顺序。

### 3.5 P5 远目标处理

- **(ii) 准入**：框架阶段且距离 > `far_admit_dist` 的目标，`min_w` 必须
  ≥ `pass_width`(0.90)；不过则 `continue`（**顺位到次远**，因为 `top` 本就是
  距离降序，天然实现降级）。
- **(iii) 中继降级**：框架阶段远目标被 veto 时，在迁移模式链最前面插入
  `relay` —— 沿 `path_and_width` **已算出**的那条路径取 4 m 弧长处继续走。
  路径与目标坐标严格匹配（`_last_path_goal`），防止用到上一个候选的残值。

**根因：`patch_sim_time` 的启动竞态。**

```bash
# 修复前（错误顺序）
retry_until 12 "$MGR" exploration_retreat_enabled true      # ← 先开闸
retry_until 6  "$MGR" exploration_retreat_max_distance_m 0.15  # ← 后设限
```

`retry_until` 带重试 + `timeout 4`，两次 `ros2 param set` 之间可以隔几秒。
而 `exploration_retreat_enabled` 的 manager 默认值**本来就是 True**，
所以"开闸"这一步毫无意义，真正的问题是：**从 manager 启动到设限生效之间，
它一直以 0.35 m / 0.10 m/s 的默认包络在跑**。

→ 退 0.302 m，超出探索期单窗包络 0.20 m（`evaluate.py:252` `explore_ok`）
→ `reverse_authorized=False` → `no_reverse` FAIL
→ 且退到 `min_d=0.004`，随后接触 13 次

**修复（已改 `patch_sim_time`，两轮迭代）**

第一版修法：「先关闸 → 设全部上限 → 最后再开闸」。

```bash
retry_until 12 "$MGR" exploration_retreat_enabled false      # ← 关闸
retry_until 6  "$MGR" exploration_retreat_max_distance_m 0.15
...
retry_until 6  "$MGR" exploration_retreat_enabled true       # ← 最后开闸
```

**但 `p14vR_far1` 实测证伪了它**：

```
:409  exploration_retreat_enabled=false ✗（超时）   ← 关闸失败
:421  exploration_retreat_max_distance_m=0.15 ✓     ← 12 s 之后才落地
:417  manager: waiting for startup map/costmap warm-up (2.1/8.0s)
```

`p14vR_far2` 同一句却是 `✓`。**时灵时不灵**＝manager 的参数服务在 patch 跑时
还没准备好，12 s 重试窗口不够。所以"关闸"这一步根本不能用来兜底。

第二版（当前）：把**真正起作用的那条上限**提到第一位，给足 30 s 等节点起来。

```bash
retry_until 30 "$MGR" exploration_retreat_max_distance_m 0.15   # ← 第一条，等节点
retry_until 6  "$MGR" exploration_retreat_speed_mps 0.05
retry_until 6  "$MGR" exploration_retreat_max_sec 2.0
retry_until 6  "$MGR" exploration_retreat_rear_margin_m 0.25
retry_until 6  "$MGR" blocked_retreat_max_per_session "$RETREAT_MAX"
retry_until 6  "$MGR" blocked_retreat_min_interval_sec "$RETREAT_IVL"
retry_until 6  "$MGR" exploration_retreat_enabled true          # ← 形式动作，放最后
```

道理：R1b 的位移上界 $=\min(\text{max\_distance\_m},\ \text{speed\_mps}\times\text{max\_sec})$。
只要 0.15 m 先落地，后面 `speed`/`max_sec` 即使还是默认的 0.10 / 3.0 也翻不出 0.15 m。
残余窗口从"12 秒级"缩到"节点应答 → 第一条 set 落地 ≈ 一次 RPC"。
`exploration_retreat_enabled` 默认本就是 True，这条只是让日志可读，放最后不再承担安全职责。

## 5. 已知限制

1. **`reg_far` / `reg_cen` 在本世界无区分度**（见 §2.1）。字段保留作诊断，
   换世界（E3）后分量可能分裂，届时有用。
2. **`far_relay_ok` 在冒烟轮为 0** —— veto 在 90 s 冒烟里没触发过远目标，
   中继路径未被真实执行。需要在完整轮次里确认。
3. **阶段仍会切换 2~3 次/轮**。虽然都是真实发现新区域引起，但切换瞬间会丢失
   "先远"的连续性。若 A/B 显示这是主要代价，可加大 `frame_hysteresis_sec`。
4. **`max_candidates`**：`launch` 默认 14，代码默认 12（launch 传参优先，
   实际生效 14）。两者不一致仅影响未经 launch 启动的场景。
5. 只测了 `aws_small_house.world`。异世界泛化未验证。
