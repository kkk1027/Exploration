# S5 实施计划：构型无关的可通行性适配层 + 几何分解区域调度

> **文档性质**：交接给实施智能体的施工图。本文档**不含任何未实测的数字**，
> 引用的数字全部来自本仓库已有文档，并标注出处。
>
> **上游决策**（用户 2026-11-13 已确认）：
> 1. 构型范围 = **差速 + 全向（麦轮/舵轮/四轮滑移）+ 阿克曼**；
> 2. 改动边界 = **仿真侧自由实现，车端仅允许 launch 级参数注入**（车端源码零提交，
>    patch 必须逐字节可还原）；
> 3. 复用原则 = 只借"可泛化、不依赖硬件"的部分，**不引入商用扫地机的单体轻量栈**。
>
> **本文档的非目标**（写进来是为了防止实施时跑偏）：
> 本仓库做的是**消费级算法落地的应用开发**，不是算法研究。因此
> "提出更优的收益函数"不是目标，"让同一套逻辑在不同构型/不同规模场景下都不崩"才是目标。

## 0. 一页摘要

### 要解决什么

当前 `frontier_arbiter` 中所有"能不能过、能不能转、能不能退"的判断，
全部以**这一台两轮差速小车**为隐含前提硬编码在代码与 launch 默认值里。表现为：

| 位置 | 现值 | 隐含假设 |
|---|---|---|
| `pass_width_m` | `0.90` | 车宽 0.47 + 两侧各 0.215（launch 注释原文） |
| `narrow_floor_m` | `0.58` | 车宽 **0.40** + 两侧各 0.09（launch 注释原文） |
| `corridor_hard_m` | `0.92`（旧硬门，已被 S3 降级） | 同上 |
| `footprint` | `[[-0.18,±0.235],[0.32,±0.235]]` | 差速底盘，能原地转 |
| 转角门 | 75°（仲裁）/ 80°（manager） | **能原地旋转** |
| 脱困 | 旋转 + 前进，禁止后退 | 移动底盘，两侧无障碍 |

**已经在仓库里被记录的口径不一致（实施时必须先解决）**：

- `pass_width` 注释用**含轮车宽 0.47**，`narrow_floor` 注释用**不含轮车宽 0.40**，
  两个阈值建立在相差 7 cm 的车体宽度上；
- `collision_probe` 的车体外接圆取 `hypot(0.29, 0.23) = 0.370 m`（底盘+轮），
  而 Nav2 footprint 的外接半径是 `hypot(0.32, 0.235) = 0.397 m`（含 padding 余量）。
  两者来自不同口径，**没有任何文档说明为何不同**。

⇒ 只要换一台车，这套阈值就必须整体重推；而重推时无从判断哪个口径是对的。
**这就是"通用性"真正的短板，也是本计划要消除的东西。**

### 要做什么（五个模块）

| 模块 | 一句话 | 是否依赖具体构型 |
|---|---|---|
| **M1 `RobotProfile`** | 车体几何与运动能力的**单一事实源**；所有阈值由它派生，代码里不再出现魔法数字 | 否（数据驱动） |
| **M2 扫掠可通行性内核** | 用 footprint 多边形沿路径**扫掠**求最小净宽，替代"切向法向测宽" | 否 |
| **M3 几何分解区域图** | 用 boustrophedon/Morse 分解替代"未知连通分量"（后者在本场景退化，见 §1.2） | 否 |
| **M4 可导航覆盖率终止判据** | 用"可达自由空间已探明比例"替代"无前沿即结束" | 否 |
| **M5 多构型验证夹具** | 三套 profile + 三种控制器配置的仿真验证 | **是**（Profile 数据不同，代码同一份） |

### 不做什么

不改车端源码、不引入 vSLAM、不做语义 NN、不换单体栈、不把覆盖率当 KPI、
不做跨会话地图续建（登记为后续，见 §7）。

## 1. 现状与证据

### 1.1 硬编码阈值分布

| 参数 | 默认 | 来源 | 换车后是否需要重推 |
|---|---|---|---|
| `pass_width_m` | 0.90 | `sim_explore.launch.py` | ✅ |
| `narrow_floor_m` | 0.58 | 同上 | ✅ |
| `corridor_hard_m` | 0.92 | 同上（S3 后降级为兼容项） | ✅ |
| `pass_width` / `narrow_floor` 使用点 | 约 21 + 多处 | `frontier_arbiter` | ✅ |
| Nav2 `footprint` | 0.50 × 0.40（外扩 0.235） | `patch_sim_time` 运行期注入 | ✅ |
| `goal_clearance` | 0.35 | 车端 manager 参数 | ✅ |
| 转角门 75° / 80° | — | `frontier_arbiter` / 车端 manager | ✅（全向不需要，阿克曼做不到） |
| 脱困策略 | 旋转+前进，禁止后退 | `escape_supervisor` | ✅ |

### 1.2 区域分解已实证退化（P14 前置阶段的实测）

`docs/P14_候选落点倾向.md` §2.1，用 `p13s4_g1` 的真实 `map.pgm`（234×386 @5 cm）统计：

| 项 | 值 |
|---|---|
| 未知格总数 | 30266（33.5%） |
| 未知连通分量数 | 150 |
| **最大分量** | **27678 格 / 69.20 m²** |
| 其余 149 个分量合计 | 6.47 m² |
| 最大分量占比 | **91.4%** |

后果（`cand_pool.jsonl` 实测，拍内归一化极差中位）：

| 特征 | 极差 | 判定 |
|---|---|---|
| `dist` | 83.4% | 可排序 |
| `u_eff` | 213.9% | 可排序 |
| **`reg_far`（所属区域最远点距离）** | **0.0%** | **无区分度** |
| **`reg_cen`（区域质心距离）** | **0.0%** | **无区分度** |
| `depth`（未知厚度） | 160.9% | 可排序 |

**结论**：连通分量在本场景里几乎是退化的——91.4% 的未知空间属于同一个分量。
按"所属区域"排序等于没排序。**这不是参数没调好，是分解维度选错了。**

商用扫地机用的是**几何分解**（扫掠线连通性变化处切开），切出来的胞腔天然有界，
"房间/区段"就是这么来的。这是本计划 M3 的依据。

### 1.3 终止判据偏弱

当前探索收敛 = "没有前沿点"。在遮挡/窄道环境下，前沿会先于"可通行空间全部探明"
消失，导致提前收敛。而这不适合"建图供下游导航"的任务——建图是**不可截断目标**
（某区域没建进去，下游导航就会失败），与覆盖任务（允许"这块不扫"）本质不同。

## 2. 设计原则（实施时不得违反）

1. **阈值不得出现在代码里**。任何"米"为单位的判据只能来自 profile 派生量。
2. **能力用 flag 表达，不用机型名分支**。禁止 `if robot == 'ackermann'`，
   只允许 `if not profile.can_rotate_in_place`。
3. **分解用几何，不用连通**。区域边界来自扫掠线连通性变化，不来自 BFS 标签。
4. **默认关闭且逐位等价**。所有新逻辑默认 `false`，关闭时必须与改造前**逐位一致**。
5. **影子模式先行**。新判据先只记录（写 timeline/cand_pool），不参与决策；
   攒够数据再切主路径。
6. **单一事实源**。车体几何只允许在 profile 里定义一次，其他所有地方引用派生值。
7. **可回退**。每个模块一个开关；回退 = 改一个参数，不需要回滚代码。

# 外廓（含轮），逆时针，单位 m。这是唯一的几何事实源。
footprint:
  - [-0.18, -0.235]
  - [-0.18,  0.235]
  - [ 0.32,  0.235]
  - [ 0.32, -0.235]

# 与 footprint 独立的"传感器/取证口径"，用于 collision_probe 的几何真值
collision_geometry:
  x_min: -0.16
  x_max:  0.29

scan_plane_height_m: 0.24   # 雷达扫描平面高度（决定哪些障碍会被 2D 雷达漏掉）

capabilities:

  side_open_m:        0.215   # 宽松行进（对应现 pass_width）
  side_tight_m:       0.055   # 极限挤过（对应现 narrow_floor 的实际几何含义）

#### 派生量（只算，不许配）

| 派生量 | 公式 | `wheeltec_diff` 结果 | 现有值 | 结论 |
|---|---|---|---|---|
| `body_width_m` | `max(y) - min(y)` | 0.47 | — | 新概念 |
| `body_length_m` | `max(x) - min(x)` | 0.50 | — | 新概念 |
| `inscribed_radius_m` | 到边最小值 | 0.235 | — | 用于 Nav2 |
| `circumscribed_radius_m` | `max(hypot(x,y))` | **0.397** | Nav2 footprint 同值 | 一致 |
| `collision_radius_m` | 由 `collision_geometry` | **0.370** | `collision_probe` 现用值 | 一致但**口径不同** |
| `pass_width_m` | `body_width + 2*side_open` | **0.90** | 0.90 | ✅ 等价 |
| `narrow_floor_m` | `body_width + 2*side_tight` | **0.58** | 0.58 | ✅ 等价 |
| `turn_corridor_m` | 见下 | 0（可原地转） | 隐含 0 | ✅ 等价 |

**阿克曼的 `turn_corridor_m`**（保守上界，用于"这条走廊够不够掉头"的预检）：

```
R_outer = hypot(min_turning_radius + body_width/2, max(|x_min|, |x_max|))
turn_corridor_m = 2 * R_outer
```

> 这是**保守上界**（假设需要 180° 掉头）。实施时必须在 `test_robot_profile.py`
> 里用解析几何断言 `R_outer` 不被低估；宁可多拒，不可放过。

#### 强制等价性闸门（Step 1 的唯一验收标准）

对 `wheeltec_diff.yaml`，派生量必须与当前代码/launch 的实际值**完全相等（容差 0）**：

```python
assert abs(prof.pass_width_m        - 0.90) < 1e-9
assert abs(prof.narrow_floor_m      - 0.58) < 1e-9
assert abs(prof.inscribed_radius_m  - 0.235) < 1e-9
```

不满足就**不许进入 Step 2**。这是整个计划的地基——地基歪了，
后面所有 A/B 都不可解释。

#### 必须解决的遗留矛盾（实施者要给出结论并写进文档）

1. `narrow_floor` 的注释（车宽 0.40）与几何真值（0.47）矛盾。
   按派生公式，`narrow_floor = 0.47 + 2×0.055 = 0.58` 恰好等于现值，
   但注释里的"两侧各 0.09"是错的（应为 0.055）。**改注释，不改数值**——
   改数值会让 S3 的 A/B 结论失效。
2. `collision_radius_m`(0.370) 与 `circumscribed_radius_m`(0.397) 并存是**故意的**
   （一个用于物理接触判据，一个用于规划膨胀）。在 profile 里用两个字段名区分，
   并在注释里写清"这两个数不同是对的"。

### M2 扫掠可通行性内核

#### 要修的既有缺陷

`docs/P1_候选生成缺陷清单.md` D2：走廊宽度按**轴向法向**测量，
斜向通道会量出 `真实宽度 ÷ cos45° ≈ 1.41 倍`。根因是 BFS 父格差只能给出
4 连通方向（`(±1,0)` / `(0,±1)`），法向必然轴对齐。

#### 做法

不用"法向测宽"，改用**扫掠**：

```
输入: 路径点序列 P、footprint 多边形 F、占用栅格 G
1. 沿 P 每 res/2 步长取位姿（位置 + 路径切向作为 yaw）
2. 把 F 的每个顶点按位姿变换到世界系
3. 检查多边形内是否有占用格（half-plane 测试 or 预计算模板卷积）
4. 同时输出 swept_min_clearance = 多边形边界到最近占用格的距离
输出: swept_clear = bool, swept_min_clearance, at_index
```

**性能约束**：不能每拍对全图做。约定：

- 只在 `/map` 或 `/global_costmap` 的 `(stamp, w, h)` 变化时重算；
- 只对**当前候选池前 N 名**（`sweep_top_n`，默认 8）做扫掠；
- 单次扫掠预算 `sweep_budget_ms`（默认 30 ms）；超预算就截断并计数
  `sweep_budget_exceeded`，**不允许**静默变慢。

#### 为什么这能带来通用性

| 构型 | 用法差异 | 代码是否需要分支 |
|---|---|---|
| 差速 | 扫掠多边形 = 矩形 | ❌ 不需要 |
| 全向 | 同上，但允许横移→路径切向不必等于车头 | 只需用 `lateral_motion` 决定位姿采样口径 |
| 阿克曼 | 扫掠需沿**转向弧**采样，不用直线 | 由 `min_turning_radius` 决定采样曲线 |

即：**同一份扫掠代码，换 profile 就能服务三种构型。**

### M3 几何分解区域图

#### 与现有实现的关系

- 现有 `unknown_region_field()`（P14/P1）**保留不动**，作为对照；
- 新增 `region_graph` 模块，**默认关闭**；
- 两者互斥：若 `region_graph_enabled=true`，则强制 `ureg_enabled=false`
  （启动时断言，防止两套区域概念打架）。

#### 算法

```
输入: 可导航自由掩码 M（= 已知自由 ∩ footprint 可放置）、地图元数据
1. 腐蚀: 用 inscribed_radius 腐蚀 M → M_erode（保证胞腔内的点车能停）
2. 扫掠分解: 沿 x 轴逐列扫描，取 M_erode 的连续区间
   - 区间"出现/消失/分裂/合并"的列 = 切分边界
   - 得到初始胞腔集合 C
3. 窄口合并: 相邻胞腔的共享边界净宽 < pass_width → 合并（否则中途过不去）
4. 小胞腔处置: 面积 < min_region_area 或 内切圆 < inscribed_radius → 标 unreachable
5. 建图: 节点 = 胞腔；边 = 共享边界，权重 = 门宽；附 per-region:
   area / centroid / unknown_ratio / frontier_count / depth
输出: region_label 栅格 + 邻接图 + per-region 特征
```

#### 区域级调度（next-best-region）

用**贪心 GTSP**（不做精确求解）：每拍对未完成区域打分，选最优区域，
再在该区域内选前沿点，交回现有排序链路。

$$\text{score}(r) = \frac{\text{unknown\_gain}(r)}{1 + \text{door\_penalty}(r)} \cdot \frac{1}{1 + d(\text{robot}, r)} - \text{history\_penalty}(r)$$

其中 `door_penalty` 来自"进入该区域必须穿过的最小门宽"，这一项**是点级排序做不到的**
——点级只知道"目标点附近多宽"，不知道"要进去得先挤过一道 0.62 m 的门"。

#### 为什么这不是"重做 P14"

`P14_候选落点倾向.md` §1 已明确：P14 要的是**点级距离排序**，
而本轮要的是**区域级结构**。两者目标不同，但失败机制有交集（都往远区推）。
P14 的失败（`p14v2_sm3` 接触 15653 次、`p14v4_home` 接触 4 次、最近 10 轮全 FAIL）
正是本模块必须解决的前置条件：

> **规则：M3 不得在"P14 已回退到 `frame_far_first=false`"的状态下开发。**
> 先把基线恢复干净，再加区域层。否则无法归因。

### M4 可导航覆盖率终止判据

#### 定义

$$\text{NCR} = \frac{|\text{已知自由} \cap \text{可导航}|}{|\text{已知自由} \cap \text{可导航}| + |\text{可达未知}|}$$

`可达未知` = 从当前位置出发，允许穿过"未知格"的 BFS 能到的未知格数
（**允许穿未知**是关键：否则窄口外的未知区永远算不到）。

#### 用途分层（重要）

| 用途 | 行为 | 默认 |
|---|---|---|
| 只记录 | 写 `timeline.jsonl` 与 `ncr` 字段 | ✅ 默认 |
| 收敛告警 | `NCR > ncr_warn_threshold` 时打 WARN + 发布状态 | 可开，`false` 默认 |
| 自动结束会话 | 调 `set_mapping_done` | **默认禁止**，且本计划不实施 |

> 理由：建图是**不可截断目标**。覆盖率型判据用于"覆盖任务"（允许区域跳过），
> 直接拿来做终止会掩盖"缺块"这种致命失败。所以本模块**只做观测与告警**，
> 自动结束留作后续单独立项（需先证明 NCR 高 ≠ 地图缺块）。

### M5 多构型验证夹具

#### 三套 profile

| profile | 场景 | 控制器（Nav2） | 通过判据 |
|---|---|---|---|

#### 关键差异（实施者必须意识到）

| 能力 | 差速 | 全向 | 阿克曼 |
|---|---|---|---|
| 原地旋转 | ✅ | ✅ | ❌ |
| 转角惩罚 | 有意义 | **无意义**（应趋 0） | 有意义但**约束不同**（受转弯半径限制） |
| 现有 75°/80° 转角软门 | 可用 | 应关闭 | **必须替换**为"转弯空间预检" |
| `escape_supervisor` 旋转脱困 | 可用 | 可用（可横移） | **不可用**，需换"前进-倒车多点转向" |
| `reverse_allowed` | false（当前） | true（可横移替代） | **必须 true**（否则无法脱困） |

> **阿克曼是最难的一档**，原因不是算法，而是现有整条链路（转角门、脱困、
> Nav2 Spin 恢复）都假定"能原地转"。实施顺序必须是
> 差速 → 全向 → 阿克曼，**不跳级**。

## 4. 实施步骤

每步都是**独立可验收、可回退**的最小单元。任一步验收不通过，不进入下一步。

### Step 0：探针与基线冻结（不改决策逻辑）

| 项 | 内容 |
|---|---|
| 交付 | `harness/probe_profile.py`（打印派生量）；`runs/baseline_frozen.jsonl`（10 轮基线摘要） |
| 验收 | 基线 10 轮指标中位数记录在案；探索段通过率、`contact`、`no_reverse`、`giveup_40s` 齐备 |
| 风险 | 基线本身不稳（当前 return-home 全 FAIL），所以**基线只冻结探索段指标** |
| 回退 | 无（只读） |

> **前置强制项**：先把 P14 回退到 `frame_far_first=false` 并跑 10 轮，
> 确认基线恢复。若基线未恢复，**停止本计划**，先修基线。

### Step 1：`RobotProfile` + 阈值派生（等价性闸门）

| 项 | 内容 |
|---|---|
| 交付 | `robot_model/` 包；3 个 profile YAML；`harness/test_robot_profile.py` |
| 改动 | `frontier_arbiter` 读取 profile，`pass_width`/`narrow_floor` 改为派生；launch 新增 `robot_profile` 参数，默认 `wheeltec_diff` |
| 验收 | ① 派生量 == 现值（0 容差）② 关闭 `use_robot_profile=false` 时 10 轮指标与 Step 0 基线无显著差异 ③ 代码中 `grep -n "0\.90\|0\.58"` 不再出现在判据位置 |
| 风险 | 等价性破坏 → 全盘 A/B 失效。**必须逐项断言，不许"差不多"** |
| 回退 | `use_robot_profile:=false` |

### Step 2：扫掠可通行性（影子模式）

| 项 | 内容 |
|---|---|
| 交付 | `sweep_kernel` 函数 + `harness/test_sweep_kernel.py`（合成栅格断言） |
| 改动 | 只在 `candidate_probe.jsonl` 里追加 `swept_clear` / `swept_min_clearance`，**不参与决策** |
| 验收 | ① 合成用例（直道/斜道/窄口/L 形）全通过 ② 斜道测量不再高估 1.41 倍 ③ 单拍 P95 增量 ≤ 10 ms |
| 风险 | 性能（每拍扫掠）；对策见 §3 M2 预算约束 |
| 回退 | `sweep_shadow=false` |

### Step 3：几何分解区域图（影子模式）

| 项 | 内容 |
|---|---|
| 交付 | `scripts/region_graph/`；`harness/test_region_graph.py`；`harness/analyze_regions.py` |
| 改动 | 每拍（或地图变化时）算区域图，写 `region_snapshot.jsonl`，**不参与决策** |
| 验收 | ① 合成用例：两个房间 + 一道门 → 必须切出 2 个区域 ② 真实 `map.pgm` 上区域数 ≤ `max_regions`（默认 40）③ 区域内切圆 ≥ `inscribed_radius` ④ 单次耗时 ≤ 100 ms |
| 风险 | 分解参数敏感（`min_region_area` / 门宽合并）；对策：先离线跑 20 份历史 `map.pgm` 定参，再上线 |
| 回退 | `region_graph_enabled=false` |

### Step 4：区域级排序（主路径 A/B）

| 项 | 内容 |
|---|---|
| 前置 | Step 3 影子数据表明区域数与门宽分布合理 |
| 改动 | `region_schedule=true` 时，排序键改为"区域分 + 区域内点级分"；强制 `ureg_enabled=false` |
| 验收 | 10+10 配对 bootstrap，见 §5-C |
| 风险 | 与 P14 同类的"推向远区"失败；对策：门宽罚分 + 区域历史罚分，且**首个远区目标必须通过 `far_admit` 净宽检查** |
| 回退 | `region_schedule=false` |

### Step 5：NCR 观测（只告警）

| 项 | 内容 |
|---|---|
| 交付 | `ncr` 字段 + `harness/ncr_report.py` |
| 验收 | 与人工标注的"地图缺块"比对 ≥ 10 轮，统计漏报率；**漏报率 > 20% 则不得启用告警** |

| 回退 | 切换回 `robot_profile:=wheeltec_diff` |

## 5. 验收指标

### A. 等价性（Step 1 门槛，硬性）

| 指标 | 判据 |
|---|---|
| 派生阈值一致 | 0 容差相等 |
| 默认关时行为一致 | 10 轮指标与基线无显著差异（配对 bootstrap 95% CI 跨 0） |
| 硬编码残留 | 判据位置 0 处魔法数字 |

### B. 性能

| 指标 | 判据 |
|---|---|
| `tick` P95 | ≤ 基线 P95 × 1.5，且 ≤ 80 ms |
| 扫掠单次 | ≤ 30 ms，超预算有计数 `sweep_budget_exceeded` |
| 区域图单次 | ≤ 100 ms，且只在 `(stamp,w,h)` 变化时重算 |
| 内存增量 | ≤ 50 MB |

### C. 行为（Step 4 主结果）

10+10 轮交错 A/B，配对 bootstrap 1000 次。主指标与判据：

| 指标 | 判据 |
|---|---|
| `cancel_rate` | 不得显著变差（CI 上界 < +10 pt） |
| `wait_ratio`（选点等待占比） | **显著下降** |
| `dist_med` | 不得显著变差 |
| `target_lifetime_med` | **显著上升** |
| `known_cells` | 不得显著下降 |
| `contact` | **= 0**（硬性） |
| `no_reverse` | **= 0**（硬性） |
| `giveup_40s` | 不得上升 |

> 通过定义：**3/5 项改善 + 0 项显著变差 + 2 项硬性归零**。
> 参考本项目已确立的判定口径（`docs/P13_实施说明.md` §15.14）。

### D. 通用性（Step 6 门槛）

| 指标 | 判据 |
|---|---|
| 每构型探索段通过率 | ≥ 7/10 |
| `contact` | = 0（三构型） |
| 阈值来源 | 100% 由 profile 派生，静态断言保证 |
| 机型名分支 | 代码中 0 处（`grep -n "ackermann\|mecanum" scripts/` 只允许出现在注释与 profile 解析） |

## 6. 风险表

| # | 风险 | 触发条件 | 影响 | 对策 |
|---|---|---|---|---|
| R1 | 等价性破坏 | 派生值 ≠ 现值 | 全盘 A/B 失效，历史结论不可比 | Step 1 0 容差断言，不通过不进 Step 2 |
| R2 | 性能超预算 | `tick` P95 > 80 ms | 饿死 lifecycle 回调（本仓库已有先例：P46-C 把车停成 228 s） | 预算硬上限 + 超限降级 + 计数告警 |

| R4 | 区域图参数敏感 | `min_region_area` 定不好 | 区域数爆炸或只有一个区域（退回 P14 退化态） | 离线用 20 份历史 `map.pgm` 定参，再上线 |
| R5 | 与 P14 概念打架 | 两套区域层同时开 | 无法归因 | 启动断言互斥；P14 先回退 |
| R6 | 基线本身未恢复 | P14 回退后仍不稳 | 任何 A/B 都不可信 | Step 0 前置强制：基线未恢复则停止 |
| R7 | 返航 FAIL 掩盖结论 | return-home 全 FAIL | 全流程判定不可用 | 验收分两套口径：**探索段指标**为主，全流程单独报 |
| R8 | 误宣称通用性 | 只跑了差速就写"支持全构型" | 学术/商业信誉风险 | README 与文档在 Step 6 通过前只写"参数化预留，已验证差速" |

| R10 | 参数爆炸 | 新增 > 10 个可调项 | 调参空间失控，A/B 无法穷举 | profile 为单一事实源，不再额外暴露派生参数；只留 3 个覆盖项 |

## 7. 明确不做（登记，不在本计划范围）

| 项 | 原因 | 重开条件 |
|---|---|---|
| 跨会话地图续建 / 多会话合并 | 大场景刚需，但涉及地图一致性、原点对齐、生命周期，风险远大于收益 | 单会话探索段稳定（探索段 PASS ≥ 9/10）后单独立项 |
| 语义障碍分类（人员/叉车/托盘） | 需要重训模型与标注，且与"构型无关"无关 | 有厂房真实数据后 |
| vSLAM / 深度相机替换 2D 雷达 | 厂房重复纹理/反光地面是 vSLAM 杀手，不适用 | 不做 |
| 覆盖率作为主 KPI | 建图不可截断，覆盖率会掩盖缺块 | 不做 |
| 改车端源码 | 违反既有纪律 | 用户明确批准 |
| 真实机器人端到端验证 | 用户自行测试 | 用户安排 |
