# P10 · 「地图和点云镜像」根因、判据与归档（2026-10-28，第 3 次复发）

> **一句话**：`session_driver` 存图时把 `nav_msgs/OccupancyGrid.data` 原样写进 PGM，
> 少了 PGM 需要的**行翻转** ⇒ 每次生成的 `maps/explore_latest.pgm` 都是 **y 镜像**；
> 任何用这张图跑台架（nav_only / nav_sim）的场景，雷达点云与地图整片错位，
> 表现为用户反复报的「地图和点云沿中轴镜像」。

---

## 1. 症状（用户视角）

- RViz 里 `/scan` 或点云**不贴墙**，整体漂在空闲区；沿某条水平轴翻一下刚好贴合。
- 伴随现象：AMCL 看起来"能定位"（近 y≈0 处镜像≈位移为 0，所以开局像正常）。
- 历史上被误判为：TF 断、DDS/网络问题、AMCL 位姿错、视觉层鬼影、fake_base y 轴镜像。
  **前两次只修了表象，所以反复出现。**

## 2. 30 秒判定法（不要猜，直接量）

```bash
# 栈在跑时执行（只读）
python3 harness/scan_map_align.py --frames 15 --tf-warm 5
```

| `as-is` | `y-flip` | 结论 |
| --- | --- | --- |
| > 90% | < 30% | 地图正常 |
| < 30% | > 90% | **地图 y 镜像（行序错）** ← 本问题 |
| 两者都低（且任何镜像轴都低） | | 位姿/TF 问题，不是镜像 |

> ⚠ **读 OccupancyGrid 必须按规范**：`nav_msgs/OccupancyGrid.data` 是 **行 0 = 最小 y（底边）**。
> 若按 PGM 习惯（行 0 = 顶边）去还原坐标，会得到**完全相反的结论** —— 我第一次就是这样
> 把镜像地图判成"99.5% 正常"，浪费了一轮。

## 3. 根因（两处代码 + 一堆镜像的读法）

| 位置 | 角色 | 约定 | 状态 |
| --- | --- | --- | --- |
| `src/stemm_cartographer_exploration_sim/scripts/session_driver` `_write_map_files()` | **写 PGM** | 必须 `img[(h-1-y)*w + x] = f(data[y*w+x])` | **已修**（原为 `img[i]=f(data[i])`） |
| `.../scripts/fake_base` `load_pgm()` | 读 PGM 做 raycast | 行 0 = 顶（`cj = h-1-int((wy-oy)/res)`） | 正确，保持不变 |
| `harness/overlay_vision.py` | 读 PGM | 行 0 = 顶（`flip_row=True`） | 正确 |
| `.../scripts/vision_obstacle_grid` `dump_grid()` | **写 PGM** | 自己 `img[cy-miny, cx-minx]`（行 0 = 最小 y）+ 自己写 yaml | **与 PGM 约定相反**；其 yaml 只有它自己用，勿给 nav2 直接吃 |
| `harness/scan_map_align.py` / `align_guard.py` / `ghost_probe.py` / `vision_src_probe.py` | 读 OccupancyGrid | 行 0 = 最小 y | **曾写错（按 PGM 翻转），已全部修** |

## 4. 实测证据（2026-10-28，nav_only 实跑）

激光末端点（20 帧，26625 点）对静态地图占据格的贴合率，容差 0.10 m：

| 地图读法 | 贴合率 |
| --- | --- |
| 按 nav2 真实约定（行 0 = 最小 y） | **15.3%** |
| 翻转读（行 0 = 最大 y） | **99.6%** |
| 扫描左右镜像（排除"雷达本身镜像"假设） | 18.2% |

⇒ 雷达是对的、世界是对的；**错的是存图行序**。
把文件行翻转后重跑：`as-is` 恢复贴合（用户现场确认"现在正确了"）。

2. **修现有坏图**：就地翻转 `~/stemm_sim_ws/maps/explore_latest.pgm`，原件备份为
   `explore_latest.pgm.bottomup.bak`（若要回看历史镜像版本用它）。
3. **加哨兵**：新增 `harness/align_guard.py`，每 10 s 自检并落 `logs/align_guard.jsonl`：
   - `hit_odom` 高、`hit_map` 低 ⇒ **AMCL 位姿错**（WMAP 之外的另一种错位，别混）
   - 两者都低 ⇒ 地图/雷达链路问题
4. **修探针行序**：见 §3 表格最后一行（否则以后还会误判）。

## 6. 防复发清单（每次出图后必做，30 秒）

```bash
# ① 出图后立刻验一次（as-is 必须 >90%）
python3 harness/scan_map_align.py --frames 15 --tf-warm 5
# ② 长跑时挂哨兵（会自己 WARN）
python3 harness/align_guard.py --period 10 &
```

代码层面三条硬规矩：

- 写 PGM：`img[(h-1-y)*w + x] = value`，**不要** `img[i] = msg.data[i]`
- 读 PGM：行 0 = 图像顶 = **最大 y**
- 读 OccupancyGrid：行 0 = **最小 y**（底边）

## 7. 判别经验（省时间用）

- **"整片错位且一次 y 翻转就能对齐" = 行序问题**；
  AMCL 错位是**平移+小角度旋转**，翻不回来（本例：AMCL 多给 0.52 m/−0.73 m/3.4°，
  翻任何镜像轴都只有 ~18%）。
- 开局"看起来正常"不代表地图对：镜像轴若在 y≈0 附近，原点附近的少量格仍会重合。
- 一旦看到镜像，**先跑 §2 的判定表**，再去查 TF/AMCL/视觉 —— 否则会像我这次一样，
  把两个不同的问题（AMCL 漂移 与 地图镜像）混在一起排查。

## 8. 同时被这次事故澄清的两件事

1. **AMCL `update_min_d/update_min_a` 不能置 0**（本轮曾为了让 TF 刷新而置 0）：
   车静止时滤波器仍每帧重采样、运动模型无信息 ⇒ 粒子云随机游走并锁到错误位姿
   （实测里程计 0.004 m，AMCL 报 0.52/−0.73 m）。已回退为原厂 0.25/0.2；
   视觉层不需要它（TF 冻结时有 `Time()` 回退，实测 med 0.03~0.12 m）。
2. **此前"视觉格 85% 离静态障碍很远"的统计口径作废**：那是拿**镜像地图**当参照算的。
   需要在修正后的地图上重算，才能回答"视觉标的是真家具还是鬼影"。
   （纯计数的指标——局部代价地图 `raw_lethal`、膨胀面积、比值——与地图朝向无关，仍然有效。）
